# 文档契约（doc-contract）

> 唯一权威，四处共用：**coding 写文档 / coding-review 审文档 / doc-fix 补文档 / doc-from-zero 反向写文档**。
> 规则只有这一份；提示词里只放引用，不复述。

## 一、为什么是契约而不是提示词

"文档够不够"必须**机械可判**，否则审查只能凭感觉，而且四处措辞必然漂移。
所以：**契约（本 skill）→ 门禁（doc-lint）→ 提示词（一行引用）** 三层，规则落在可执行的地方。

## 二、条目模板（按类型）

### 2.1 入口点（CLI 命令 / HTTP 端点 / 事件处理器 / 公开导出）

必填：**用途** · **输入**（参数/请求体：名、类型、必填、默认）· **输出**（形状、示例）· **错误**（码/状态码、触发条件、错误体形状）· **示例**（可直接复制执行）

### 2.2 模块 / 包（`type: module`）

必填：**职责**（这个文件/包负责什么、不负责什么）· **公开成员**（导出什么，逐个指向其条目文档）· **依赖**（上游模块、外部依赖）

为什么单独一类：覆盖审计只认「有一篇文档自报家门说这就是某模块」或「总览链接到它」。
只在 Runbook 里被提一句不算覆盖——否则单元被整篇跳过也能显示 100%。

### 2.3 公开函数 / 方法

必填：**摘要** · **行为语义**（边界条件、幂等性、副作用）· **参数**（类型、约束、默认）· **返回** · **异常**（类型与触发条件）· **示例**（公开 API 建议有）

### 2.4 公开类 / 接口

必填：**职责**（做什么 / 不做什么）· **构造或初始化** · **公开成员**（含义、可变性）· **生命周期** · **典型用法**

### 2.5 配置项

必填：**名称** · **类型** · **默认值** · **是否必填** · **取值范围** · **影响**（改了会怎样）· **示例**

### 2.6 数据模型 / 存储

必填：**字段**（名、类型、约束、可空）· **索引/唯一约束** · **生命周期**（谁写、何时删）· **关系** · **迁移注意**

### 2.7 错误码

必填：**码/标识** · **含义** · **触发条件** · **客户端应如何处理**

## 三、必填节的严格度（分级表固定，不由作者自判）

| 条目类型 | 缺节判定 |
|---|---|
| 入口点 / 公开函数 / 公开类 / 配置项 / 数据模型 / 错误码 / 模块 | **缺必填节 = FAIL** |
| 内部 / 私有符号 | 摘要 + 行为语义即可；缺则只记 finding，不 FAIL |

**N/A 规则（硬）**：确实不适用时必须写 `N/A` 并给理由（如"无参数"）。
**省略不等于不适用**——缺节且无 N/A 声明，一律按缺节处理。

## 四、反模式（禁止项）

| 反模式 | 为什么禁 |
|---|---|
| 复述代码（把实现抄一遍） | 代码一改文档必错，且没有增量信息 |
| 整段粘贴日志/输出 | 噪声，无法验证 |
| `TODO` / `TBD` / "后续补充" | 未完成就是未完成，不许伪装 |
| 承诺未实现的行为 | 文档说的必须是代码做的 |
| 引用不存在的实体 | 幽灵引用；不查真实性时朴素写法存在率只有 ~61% |
| 用篇幅凑"完整" | 密度原则：篇幅由信息量决定，与问题数量成正比 |

## 五、真实性规则（机械可判）

1. 文档提到的每个**代码实体**（函数/类/方法/端点/配置键/路径/表字段）都必须真实存在
2. 引用必须可回指：`path:line` 或可重放的命令
3. 汇编层（总览/架构/数据流）出现的每个新事实都必须能追溯到叶子证据——**上层断言不许凭空**

## 六、门禁（doc-lint）检查面

| 检查 | 判定 |
|---|---|
| 实体存在性 | 任一符号/路径/配置键不存在 → **FAIL**，逐条给行号 |
| 必填节 | 按类型查（§三 分级表）→ 缺节 FAIL（内部符号只记 finding） |
| 链接可解析 | 相对路径与锚点解析失败 → **FAIL** |
| Runbook 七件套 | 环境要求 / 依赖安装（含测试侧获取与隔离）/ 配置项 / 启停+健康检查 / 种子数据 / 测试运行 / 公开接口清单 → 缺一件 **FAIL** |
| 禁止项扫描 | 超大代码块 / 日志粘贴 / TODO 标记 → 提示（不直接 FAIL） |
| 同名异写 | 同一实体出现多个名称 → 提示，终审时判 |

要求：**能给出具体行号、退出码可判（0 = 通过）**。给不出定位的检查等于没有检查。

## 七、写作要求（写文档的人先看这一条）

- **第三方（人或 Agent）只靠文档就能写测试、能跑起来**——这是合格线，不是加分项
- 文档里出现的每个行为都要有落点：谁触发、什么输入、什么输出、失败长什么样
- 不确定的原因写 `（推断：依据xxx）`，别冒充事实；查不到就写进缺口，别编

## 八、与 doc-from-zero 的关系

反向写作（陌生库 → 文档体系）**复用同一份契约**：条目模板同源，必填节同源，真实性规则同源。
唯一额外的是「覆盖」——清单每一条都要有文档落点，那是反向写作特有的分母，不进本契约。
