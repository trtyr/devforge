# Open Questions — P004

## Q001 · 项目与本地目录怎么绑定？

项目在本地怎么「建立关系」：统一 workspace 约定（如 `~/devforge-workspace/<project>/`，从 0 的项目立即建目录）vs 用户指定已有路径（项目已有代码时挂接）vs 两者都支持（创建时选）？

倾向：MVP 两分支——从 0 项目按约定路径建目录，已有项目用户指定路径。待拍板。

## Q002 · SOP 的 MVP 形态？

规划 SOP（P001 状态机）MVP 阶段代码内置在编排器里（任务创建时引用内置 SOP 标识），还是第一天就把剧本做成数据文件（配置描述状态机）？

倾向：MVP 代码内置（状态机是手写 Rust 逻辑，数据化是远期重构，见 roadmap Deferred）。待确认。

## Q003 · 并发的实现时机？

任务层正式需求含并发（同项目多任务、跨项目多任务）。架构原料（run-id 隔离、按 run 落盘、台账）已天然支持。MVP 是串行起步（一次一个任务）还是直接并发？

倾向：架构按并发设计（数据模型与隔离天然多 run），实现 MVP 串行起步、并发随后放开——代价小。待拍板。

## Q004 · 任务重跑语义？

任务重跑（规划失败重来 / 重新规划）：默认新 run、旧 run 产物（plan tree 历史、session、日志）留档可溯，任务当前产物指向最新 run。此为默认设计，可推翻。
