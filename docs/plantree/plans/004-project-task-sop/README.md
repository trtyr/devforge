# P004 · 项目/任务/SOP 三层管理

## Scope

devforge 的对象模型与生命周期管理。系统的主要功能点是 MVP 流水线，流水线的宿主是三层对象（用户拍板 2026-10-16）：

| 层 | 是什么 | 与本地的关系 | 管理内容 |
|----|--------|--------------|----------|
| **项目层** | 代码开发项目，最高层级 | 项目怎么跟本地建立关系（本地目录绑定，机制待定 Q001） | 项目 CRUD、元数据、列表 |
| **任务层** | 项目下的工作单元，绑定一个 SOP 跑流水线 | 任务怎么在项目下管理 + 任务与本地关系（落盘 `plans/<项目>/<任务>/`，未来工作目录） | 任务 CRUD、生命周期（创建/运行/完成/失败/归档）、**并发**（同项目多任务、跨项目多任务，Q003） |
| **SOP 层** | 可复用的流水线剧本 | 无本地落盘（MVP 代码内置，Q002） | SOP 定义、与任务的实例化关系 |

**关键关系**：任务 : SOP = 实例 : 模板。P001 设计的规划流水线 = 第一个 SOP（规划 SOP）的内容；任务是它的一次运行。

**run 与 task**：task 是逻辑单元（有生命周期），run 是执行实例（有 run-id）。任务重跑 = 新 run，旧 run 产物留档（Q004 默认）。并发隔离的原料已就位：run-id 身份体系 + 按 run 的 session/日志落盘 + 按任务隔离的 plan tree。

## 能力域归属

- 三层的数据模型与生命周期 → 本 plan
- 单 run 的编排引擎 → P001（不变）
- API 出口 → P003 编排控制/产物管理域（端点随本 plan 数据模型定稿后细化）
- 配置供给 → P002（Agent profiles 与三层无关，是横切供给）
