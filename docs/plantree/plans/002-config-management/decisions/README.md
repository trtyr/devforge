# Decisions — P002

稳定决策记录。只记「选了什么 + 为什么 + 后果」。

---

## 001 · Key 明文，安全不设防

- **决策**：API Key 明文存清单，不做加密、不接钥匙串。安全维度整体不管，未来也不管
- **为什么**（用户拍板）：明文就明文，无所谓；与 pi 本机 auth.json 同一水位
- **后果**：清单文件就是敏感文件，但不需要任何额外防护设计；Q001 结案

## 002 · 模板化：基座写死，不搞通用 CRUD

- **决策**：公共基座（提示词、必装插件、skills、MCP、Key）写死成模板；Agent 间的差异收敛到极小维度（见 003）。不设计通用配置 CRUD 系统
- **为什么**（用户拍板）：所谓基座+差异覆盖，说白了就是模板——写死就可以了
- **后果**：P002 的「内部管理」大幅瘦身：不是给每类配置做通用编辑器，而是维护模板 + 少量可变项；Q003 结案

## 003 · 维护收敛律：最终只有模型可自定义

- **决策**：系统定型后，唯一长期开放的自定义维度 = **每个 Agent 用什么模型**。其余一切最终写死：提示词定稿即定死、skills 定死、MCP 系统级定死（用户亲自选定哪些 MCP 进系统）。唯一例外：插件版本——插件走安装模式，版本随安装流动，不锁死
- **为什么**（用户拍板）：现在全量维护是因为还要开发调试；未来做好之后东西都定死了，能自定义的就只剩模型
- **后果**：① 清单 schema 按两层设计：模板层（写死）+ 模型层（每 Agent 可变）；② MCP 不做每 Agent 自由配置，系统级一份（Q004 方向定案，具体 MCP 清单待用户后续敲定）；③ 自动更新主要服务开发调试期，定型后该能力自然闲置——不是问题，是终态
