## 仍开放

### Q004 · 并行度与一致性（术语表）

并行写作时同一概念可能被不同 agent 用不同术语描述。是否需要写作前先立一份 **glossary**（术语表），汇编时按它归一？
（CodeWiki 的做法是全局引用登记表 + 汇编时归一）

### Q005 · 审查者的角色

- 复用 `doc-review`（极简、只审文档一致性）？
- 还是需要专用变体（要跑 codegraph 查实体存在性、要能手算覆盖率、要跑 doc-lint）？
- 考虑到审计是**确定性检查为主**，审查官可能只需要"跑工具 + 判结果"，那么极简 profile 够不够？

### Q006 · 完成判据的严格程度

- 严格：inventory 覆盖率 100% 且真实性 100%
- 现实：允许显式缺口（"这部分代码无行为可文档化" / 反编译产物 / codegraph 不支持的语言），但缺口必须登记

### Q008 · 必填节的严格度

缺一项就 FAIL，还是按条目重要性分级（入口点/公开 API 严格，内部函数宽松）？

### Q013 · 旧 `docs-update` 链怎么办

doc-init 退役后，"增量对齐"失去上游。选项：
- 本 SOP 内置增量模式（清单差异 → 只重写变动模块）
- 或单独立项（与 docs-update 合并设计）
