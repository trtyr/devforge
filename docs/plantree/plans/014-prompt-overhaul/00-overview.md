# P014 · 提示词体系全面改造（2026 提示词工程标准）

## 一、背景与动机

三重证据链指向同一结论——提示词是当前质量短板：

1. **复验报告实证**：审计批次协议违例 2 次、change 重入话术缺失导致步号对账误报、
   route-plan 申报语义不清——全部是提示词边界没讲清的直接后果。
2. **M3 自审挂死**：审查 agent 探查仓库时跑挂死命令——提示词没有「禁止长时阻塞命令」
   的边界约束。
3. **用户判定**：「系统提示词写得太水了」（2026-10-25），并要求按 2026 年最新指南全面改造。

## 三、现状盘点（2026-10-25）

14 条提示词、597 行、~12K token（平均 900 token/条）：

| 家族 | 文件 | 行数 |
|---|---|---|
| change 规划 | change-plan-agent / change-plan-review | 60 / 38 |
| change 编码 | change-coding-agent / change-coding-review | 56 / 27 |
| change 测试 | change-test-agent / change-test-review | 35 / 23 |
| coding 家族 | coding-agent / coding-review | 66 / 42 |
| 审计 | code-review-agent | 39 |
| doc 家族 | doc-agent / doc-fix / doc-review | 57 / 21 / 29 |
| testing | test-agent / test-review | 60 / 44 |

**共同结构缺陷**（对照六块标准逐条诊断）：

- ❌ 规则不带原因（「必须输出 <stage-complete>」没说为什么——模型不知所以然无法泛化）
- ❌ 无边界情况段（没有输入为空/歧义/超界的处理指令——N1 空转与协议违例的根因之一）
- ❌ 无「不知道」路径示例（模型天性硬答——审计幽灵发现的诱因）
- ❌ 禁止式约束无正向替代（「不要读代码」没说「事实从引擎注入的审计段拿」）
- ❌ 无 XML 边界（数据/示例与指令混排）
- ✅ 已有的：输出协议块（<stage-complete>/<audit-findings>/<verdict>）、流程步骤、视角清单

## 四、改造设计

### 统一骨架（六块，每条提示词重排为此结构）

1. **身份**（≤2 句）：角色 + 读者状态（谁消费产出、在什么场景）。
2. **硬约束**（最前，吃注意力峰值）：每条带原因；禁止必带正向替代。
3. **流程**：编号步骤 + 每步的判定标准（四型模板适配：分析型走扫描→深挖→综合→排序；
   生成型走理解→设计→生成→自验；验证型走装标准→逐条→判 PASS/FAIL）。
4. **边界情况段**：空输入/歧义/超界/「不知道」——明确处置动作。
5. **输出契约**：协议块形态 + 错误时行为（不许自由文本混入）。
6. **示例**（仅格式硬需求时）：含至少一条「不知道」路径示例，XML 包裹贴尾部。

### 硬性纪律

- 每条 ≤1200 token（现状 900 均值，重排不增重；新增内容从删除冗余中换）。
- 每一行必须能回答「这行修的是哪个真实见过的失败」——答不出就删。
- 能用引擎机械校验的约束（协议块形态）不靠提示词祈祷——引擎已有 verify 层的保持引擎管。
- 动态内容（change-id/基线等运行时值）不进提示词正文，保持 kickoff 注入通道。

### 验收检查表（每条提示词改造后逐项过）

- [ ] 六块齐备且顺序正确
- [ ] 每条硬约束带原因 + 禁止带正向替代
- [ ] 有边界情况段（含空输入与歧义处置）
- [ ] 输出契约含错误时行为
- [ ] ≤1200 token
- [ ] manifest pinning 测试同步 + 全目标 cargo test 绿

## 五、范围

- **主战场**：devforge 14 条提示词资产（assets/prompts/，include_str! 进 manifest）。
- **次战场（M5）**：pi 侧系统提示词（personality + APPEND 工作栈）按同标准审改——
  在 pi-config 仓，与本计划同方法论、独立提交。

## 六、非目标

- 不改引擎对提示词的注入机制（kickoff/facts 通道不动）。
- 不做提示词 A/B 评估基建（2026 口径的「提示词即评估」留待后续计划——本轮以检查表 +
  测试级验证为验收）。
- 不改 SOP 流程结构（只改提示词文本层）。
